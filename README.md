# 天主教神哲学翻译skill

**让 AI 翻译天主教文献时，把原文、术语和历史语境一起带上。**

`catholic-text-translation` 是一套面向中文读者的 AI 翻译工作规范，适用于天主教哲学、经院神学、教父、公会议、训导及礼仪文献。它把底本核验、专业术语、圣经引文、分批续译和译文复校组织成可重复使用的流程，帮助你得到更容易核查和修订的中文译稿。

**中文输出 · 拉丁文重点 · 专业术语 · 来源追溯 · 长篇续译 · 译文复校**

[快速开始](#quickstart) · [功能介绍](#features) · [使用示例](examples/prompt-examples.md) · [已有测评](#evaluation) · [参与改进](CONTRIBUTING.md)

> 第一次接触 Skill？可以把它理解为“给 AI 的专业工作手册”。安装后，你提供原文和翻译要求，AI 按这套手册工作。这个仓库包含规范、参考材料和一个覆盖记录检查脚本；翻译本身由你使用的 AI 完成。

## 为什么做这个项目？

天主教哲学与神学翻译中，一个译词、一处否定或一个修饰关系，都可能改变整句话的意思。中文读起来流畅，还需要回到原文检查：谁在说话？他说的是谁？限定条件有没有保留？译名是否适合这个时代和作者？

本项目围绕这些实际问题设计流程：

| 翻译时遇到的问题 | Skill 要求怎样处理 |
|---|---|
| `substantia`、`essentia`、`natura` 的区别在中文里被抹平 | 根据作者和句境区分实体、本质、本性，记录术语选择与例外 |
| 只看到英文参照，却把译稿写成“拉丁文直译” | 按实际底本标明直接翻译或转译，保留来源身份 |
| 把会议草案、最终文本和编者附录混在一起 | 先辨明文献身份和修订阶段，在译稿及目录中分别标识 |
| 分批翻译后，译名反复变化、段落重复或遗漏 | 继承项目术语，保存进度，核对原文单元与译文的对应 |
| 现成译本引用了部分圣经经文，AI 却补成整节 | 核对文献实际引到的文字，保留节引边界和版本差异 |
| 润色后句子更顺，但条件、否定或指代变了 | 先核验意义，再调整中文，最后回查改动处的原文 |

## 快速开始

### 1. 安装完整技能目录

在支持技能安装的 Codex 环境里，把下面这段话发给内置的 Skill Installer：

```text
请使用 $skill-installer，从这个 GitHub 仓库安装 catholic-text-translation：
https://github.com/zhangjasony-commits/catholic-text-translation
技能的 SKILL.md 位于仓库根目录，请一并安装 references、scripts 和 agents。
```

也可以[下载仓库 ZIP](https://github.com/zhangjasony-commits/catholic-text-translation/archive/refs/heads/main.zip)，解压后将完整文件夹命名为 `catholic-text-translation`，放到当前环境支持的技能目录。按当前 OpenAI 官方文档，Codex 的用户级本地目录是 `~/.agents/skills/`；项目级目录是 `.agents/skills/`。保留整个文件夹，避免只复制 `SKILL.md` 后丢失它引用的材料。

安装后检查技能列表是否出现“天主教文献翻译”或 `catholic-text-translation`；若未出现，重新启动 Codex。不同客户端的入口可能不同，具体以 [OpenAI 官方技能文档](https://learn.chatgpt.com/docs/build-skills)为准。本仓库以独立 Skill 目录形式提供，尚未发布到插件目录。

### 2. 提供原文，直接提出任务

在支持 `$` 调用的 Codex 环境中，可以复制：

```text
请使用 $catholic-text-translation，将我提供的文献翻译为简体中文。
先确认底本语言和文献版本；保留标题、条号和注释关系。
专业术语按天主教语境处理，圣经引文参照思高译本。
只交付中文译文、必要译注和未解决的问题，并注明自译身份。
以下是原文：
【粘贴原文，或提供可读取的文件】
```

能选择技能的客户端，也可以在技能选择器里选中它，再输入任务。其他 AI 环境可将本仓库作为工作规范参考，但需自行确认能否读取引用文件；仅粘贴一段提示词不等于已加载全部技能。

### 3. 从一个完整段落开始

先用短篇试译确认术语和文风，再扩展到整章或整卷。长篇任务可指定“每批一个完整章节”“沿用现有术语表”“继续上一批”，并要求保存进度。

你通常会得到：**中文译文、必要译注、来源与版本说明、局部未解项**。术语表、覆盖记录及 Word／PDF 按任务需要生成。

## 功能介绍

### ① 底本核验：先弄清到底在翻译什么

要求 AI 查看文件实际内容、标题、首尾和章条结构，辨明原文、译本、草案、修订文本及编者材料。多文件任务会比较重合范围，识别独有序言、附录或缺页；有依据的重复内容可只译一次并保留对应。

检索能力可用时，按需要比较可靠原语言见证和参照译本。不同版本有实质差异时说明选择，不把几个版本悄悄拼成一个新文本。扫描件的关键页需要查看页面图像，OCR 用于辅助定位。

### ② 专业术语：把译名放回作者和时代

内置天主教术语候选表和语境提示，涉及恩宠、成义、圣事、位格、本性、实体、现实与潜能、首席权及训导等概念。候选译法用于帮助判断，不要求所有作者、时代和文体都一词一译。

| 术语组 | 重点检查 |
|---|---|
| `substantia / essentia / natura` | 实体、本质与本性的区别 |
| `persona / hypostasis / suppositum` | 位格与主体相关概念的历史用法 |
| `actus / potentia / esse` | 经院语境中的现实、潜能与存在；也注意非技术用法 |
| `gratia / iustificatio` | 恩宠与成义的神学语境 |
| `latria / hyperdulia / dulia` | 钦崇礼、超敬礼与敬礼；具体动作仍按句义判断 |
| `validus / licitus` 相关表达 | 有效与合法的区别 |

长篇项目记录原词、语境、译法、依据、状态和例外。译名有证据需要更正时，回查正文及译注中的相关位置，避免对多义词直接全局替换。

### ③ 拉丁句法复核：保留改变意义的小词和关系

重点检查格与修饰配合、代词先行词、属格层级、间接陈述、分词、条件、义务表达，以及否定和“仅限”等词的作用范围。教义定义、谴责公式和哲学论证中的主体、对象与限定不能被润色省掉。

例如，已有纠错材料用 `Filius Dei vivi` 提醒检查“生活的”修饰谁；用 `damnamus illorum sententias` 提醒区分“谴责那些人的意见”与“谴责那些人”。这些例子服务于句法检查，具体出处和处理见[句法复核与纠错](references/translation-review.md)。

### ④ 圣经引文核验：译出文献实际引用的内容

中文经文默认参照思高译本，也可按用户指定版本处理。流程要求核对书名、经节、引文范围及文献实际文字；区分直接引文、节引、意译和典故。

若所引武加大、古拉丁或其他文本与中文参照存在实质差异，优先忠于文献所引文字，必要时自译并说明。无法读取参照正文时，明确保留未核验状态。

### ⑤ 历史与文献身份：让译稿说清楚谁在说什么

区分作者主张、异议、引述、答复、原注、编者说明和译注。草案中的拟议措辞仍标作草案；历史制度和礼仪名称按当时语境处理。

这套规范要求保留原文立场与限定，不用后来的精确定式改写早期文本，也不因为某个术语熟悉，就自行给整段增加教义等级或学派结论。

### ⑥ 长篇续译与合卷：让进度和缺口有记录

按完整章节、条款或论证段落分批，保留必要邻文和跨段指代。每批继承底本选择、术语及例外，记录最后完成位置和下一步；合并后检查衔接处。

复杂任务可以保存来源清单、项目术语表、经文对照、修正记录、覆盖记录和项目状态。重叠段落作为上下文时，不重复计入交付。多文件合卷会分别说明正式文本、草案及编者附录的范围。

### ⑦ 译文复校：查意义，也查中文是否自然

工作顺序是：**语义初译 → 查明问题 → 修订 → 中文通读 → 改动处回查原文**。

用户指出错误后，要求核验整个句子和必要邻段，再追查同类结构，同步正文、译注及当前交付版本。真实误译、可接受异译、表达改善和排版问题分别记录，避免把措辞不同都算作错误。

### ⑧ 多语言与文件交付：按实际环境使用

以拉丁文文献为重点，也提供英语及其他源语言译入中文的处理流程，包括法语、德语、日语等语境中的从句、指代和同形词风险。不同语言的实际效果取决于模型、底本和参考资料；已有测评没有覆盖全部语言。

可处理环境中能够读取的粘贴文本及文件；PDF、Word、扫描件涉及的抽取、OCR、导出和视觉检查，由宿主环境的相应工具承担。Skill 会要求说明完成了哪些检查。仅交付纯文本时，不声称完成了版面检查。

### ⑨ 覆盖记录检查：发现漏项和失去对应的译文

附带的 [`audit_coverage.py`](scripts/audit_coverage.py) 只依赖 Python 标准库，可检查预先建立的 JSON 覆盖记录，报告遗漏ID、重复ID、空译文、无效对应和待译项。

```text
python scripts/audit_coverage.py coverage.json --report coverage-audit.json
```

从技能根目录运行；记录格式和返回码见[覆盖记录说明](references/coverage-ledger.md)。短篇翻译通常不需要运行它。

**这个脚本不读取原文正文，不判断译文是否等义，也不证明来源清单本身完整。** 它帮助管理覆盖情况，语义检查仍要回到实际原文。

## 适合哪些人、哪些任务？

| 使用者 | 可以从什么任务开始 |
|---|---|
| 哲学与神学研究者、学生 | 经院论证、教父段落或教材章节的试译与术语核对 |
| 公会议与教会史文献读者 | 正式文件、草案和历史注释材料的版本辨别与翻译 |
| 中文译者和校订者 | 对照原文检查译稿，整理术语、误译和可接受异译 |
| 礼仪与圣经相关文本读者 | 核对祷文、文献引经及历史名称 |
| 长篇翻译项目维护者 | 分批续译、合卷去重、补缺记录和进度交接 |

本项目主要用于翻译、译文校订和翻译准备。一般教义问答、独立的教会法个案裁断或完整思想史研究，需要另行选择适用的方法与资料。

## 已有测评与实际边界

仓库的[首轮测评记录](references/benchmark-and-risk-cases.md)记载：2026-10-09，对五份梵二正式文献中的 **17 个拉丁文短片段**进行试译，保存初稿后与有机构署名的中文译本比较，并对难点参照英文及思高经文。

记录报告未检出已证实的核心含义误译，同时发现中文表达、清晰度和一致性方面的改善项。它也把人工参照中的内容或范围差异单列，避免把现成译本的所有措辞当作唯一答案。

**这是小范围、定向的短片段测评。** 它没有无技能对照组，不能据此给出总体准确率、技能提升百分比、其他语言能力或整卷无误的结论。模型复核与人工参照比较，也不等同于新增人工审校。

本项目提供可检查的流程约束，最终质量仍取决于原文清晰度、版本和资料可得性、模型执行及后续校订。译稿应注明自译身份，不能冒称官方中文译本；公开出版前仍应安排适当的人工复核。

## 常见问题

**必须会编程吗？**  
日常翻译不需要。安装技能、提供原文和要求即可。覆盖检查脚本是复杂长篇项目的可选工具。

**可以不联网吗？**  
可以限定只使用所给材料，但无法完成的外部版本、引文和缺页核验需要明确说明。联网功能由宿主提供，仓库本身没有联网服务。

**会不会默认改成现代天主教的说法？**  
规范要求先尊重作者、时代和所选文本，历史名称和观点按实际语境处理，必要说明放入译注。

**能保证不出错吗？**  
不能。它规定核验与纠错方法，并保留未解决的问题；重要段落仍需逐句回查原文。

**许可证是什么？**  
当前仓库尚未添加 `LICENSE` 文件，授权范围由作者另行说明。
